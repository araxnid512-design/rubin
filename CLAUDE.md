# Памятка для Claude: игра «Улей. Кластер-17»

Эту памятку читает новый чат Claude Code, который продолжает работу (например, с другого аккаунта). Здесь
сказано, что уже сделано, как устроен код и по каким правилам работать. Подробное описание игры — в `README.md`.

## Правила работы

- **Основная версия — браузерная (`game/`, `game.html`; APK — она же в WebView).** 2026-11-03 пользователь вернулся к
  ней из Godot: «вернёмся к проекту не Godot, а тот, что был до этого, только оружие используем новое». Godot-версия
  (`godot/`) заморожена: не развивается, её CI («Godot-версия») запускается только от правок в `godot/` или вручную.
  Из Godot перенесено только новое оружие (п. 17). Помощники (субагенты) разрешены.
- **Ассеты и механики — бесплатные, где можно** (просьба пользователя для этой игры и будущих): CC0
  лучше всего, CC-BY — с авторами в `godot/assets/external/LICENSES.md`; не брать платное и «рипы» из
  коммерческих игр. Каталог — `docs/assets-catalog.md`, скачивание в CI — `scripts/fetch-assets.mjs`
  (из облачной среды большинство сайтов ассетов закрыто; открыт raw.githubusercontent.com).
- **Перед любой работой с Tripo читай `docs/tripo/TRIPO_RULES.md` и соблюдай его** (пакет правил пользователя:
  бюджет и журнал `docs/tripo/tripo_budget.md`, список `ASSET_LIST.md`, шаблоны `PROMPT_TEMPLATES.md`; перед
  платной операцией — план и «ок» пользователя). Кредиты сайта Studio тратит программа tripo после входа по
  аккаунту (CI «Tripo (аккаунт)», `scripts/tripo-login.sh`, задания — ветка `tripo-control`); ключ API берёт
  кредиты из отдельного кошелька (там 0).
- **Ориентир по картинке** — концепт «STIKS_location_concept_v1» из пакета пользователя и мобильная
  Dawn of Zombies: Survival; **FPS на телефоне — главное**: любые улучшения — с замером и профилями
  качества Низкое/Среднее/Высокое.

- **Язык — русский:** общение с пользователем, тексты в игре, комментарии в коде, сообщения коммитов.
- **Ветка — `ccr-f5d34f3a-q7wlgf`:** работать в ней и пушить в неё же (`git push -u origin ccr-f5d34f3a-q7wlgf`).
  Сборку APK и страницу скачивания запускает только пуш в эту ветку или в `main`
  (`.github/workflows/offline-release.yml`). Изменения из другой ветки до игроков не дойдут.
- Pull request — только если пользователь попросит.
- После каждой правки: тесты (см. ниже), коммит, пуш, короткий отчёт пользователю — что изменилось
  и где скачать.
- В коммиты и код не вписывать названия и идентификаторы моделей ИИ.
- Не коммитить ключи и пароли. Единственное исключение — `android/app/debug.keystore`: это **открытый**
  debug-ключ (пароль `android`, alias `androiddebugkey`), тот же, что у прошлых игр пользователя
  («Стикс», «Клоны»). Не менять его: иначе новый APK не встанет поверх старого.

## Где игра у игроков

Каждый пуш в ветку (если менялись `game/**`, `game.html`, `android/**`, `assets/**` и т. д.) пересобирает
релиз «game» на GitHub — ссылки постоянные, открыты всем:

- APK для Android: https://github.com/araxnid512-design/rubin/releases/download/game/ulei-cluster17.apk
- тот же APK в ZIP: https://github.com/araxnid512-design/rubin/releases/download/game/ulei-cluster17-apk.zip
- игра одним HTML-файлом (без интернета): https://github.com/araxnid512-design/rubin/releases/download/game/ulei-cluster17.html
- страница игры выкладывается в ветку `gh-pages`, папка `ulei/`, но GitHub Pages в репозитории выключен:
  чтобы она открылась по https://araxnid512-design.github.io/rubin/ulei/, пользователь включает
  Settings → Pages → Deploy from branch → `gh-pages`, `/ (root)`.

Номер сборки — номер запуска workflow (`1.N`, он же `versionCode` APK). Игра сама проверяет, вышла ли новая
версия, и предлагает скачать (`game/version.js` пишет `scripts/build-offline.mjs` — файл коммитится).

Версия в Claude (artifact) у прошлого аккаунта личная: новый аккаунт её не откроет. Чтобы играть
в Claude, публикуют свой artifact: `game.html` + файлы `game/**`, `models/game/*`, `assets/**` (или
собранный `download/ulei-cluster17.html`).

## Команды

```bash
npm ci                 # зависимости (three 0.170, esbuild, playwright уже есть в облачной среде)
npm start              # http://localhost:8080/game.html
npm run test:game      # браузерный тест всей игры, ~15 минут, должно быть «GAME E2E: OK» (сейчас ~155 проверок)
npm run test:offline   # сборка download/ulei-cluster17.html и проверка без сети
npm test               # тест модели зомби
node scripts/render-previews.mjs   # снимки локаций для карты Улья (assets/previews/*.jpg)
```

Тесты ускоряют логику (`?sim=30`) и подменяют CDN three.js на `node_modules`. Chromium для Playwright
в облачной среде уже стоит — `playwright install` не запускать. Долгий тест удобнее гонять в фоне и
следить за строками `✗` в логе.

## Как устроен код

- `game.html` — вся разметка и стили интерфейса (окна, HUD, меню); `game/main.js` — игра: акторы
  (`Player`, `Enemy`, `Merc`, `Bandit`), `fireShot`, отряды муров (`RaidSquad`, `Garrison`), объект `game`
  (доступен в тестах как `window.__game`).
- `game/level.js` — сборка уровня из `game/locations/*.js` (Заречный, Дачи, Химмаш, Военная часть, Больница,
  Лесопилка, Подстанция, НИИ, Деревня Бор, Ж/д станция, Микрорайон, Аэродром, стаб «Полис», стаб муров «Карьер»,
  база «Опорный», форпост внешников); `game/changes.js` —
  завалы после перезагрузки; `game/geom.js` — `Batch` (слияние геометрии по участкам для отсечения);
  `game/props.js`, `game/props-industrial.js`, `game/buildings.js` — постройки и предметы.
- `game/world.js` и `game/worldmap.js` — карта Улья (пояса `ZONES`), время мира, перезагрузка кластеров;
  `game/minimap.js` — миникарта и план локации.
- `game/horde.js` — сколько и каких заражённых на цикл (по опасности кластера, стаи с вожаками).
- `game/weapons.js` — оружие (модели и характеристики), `game/items.js` — предметы, `game/trade.js` —
  торговец, `game/stash.js` — хранилище, `game/inventory.js` — рюкзак.
- `game/mods.js` — доработка стволов в мастерской (прицел, глушитель, магазин, тормоз); `game/mercs.js` — наёмники
  (классы, окно отряда, посты и вылазки с базы); `game/murs.js` — учёт муров (вылазки, наём,
  запасы, настройки их стрельбы); `game/ext.js` — учёт внешников (охоты, форпост, пленные); `game/migrant.js` — кочующая
  стая; `game/quests.js` — доска заданий; `game/raids.js` — налёты на базу; `game/base.js`, `game/terminal.js`,
  `game/base-buildings.js` — база героя (постройки и уровни, терминал, здания с интерьером); `game/intel.js` — информатор; `game/marks.js` — следы боя (кровь, дырки, гарь);
  `game/ground-detail.js` — детали и неровность цвета земли.
- `scripts/build-offline.mjs` — один HTML-файл и `android/app/src/main/assets/index.html`;
  `scripts/build-ulei-site.mjs` — страница игры; `android/` — приложение (WebView, minSdk 23).

## Что уже сделано (по просьбам пользователя, по порядку)

Кластеры, перезагрузка, карта Улья, стаб с торговцем и лекарем, оружие и патроны по калибрам, прочность
топора, гранаты, рюкзак, хранилище, гибель (валюта остаётся, вещи — на месте гибели), руберы и чёрная
жемчужина, звуки, атмосфера, расчленение, разрушаемость, интерьеры. Затем:

1. **Наёмники:** живут в комнате героя в стабе (6 коек; с п. 29 — ещё и на базе), снарядить, взять или оставить — только там;
   без патронов гибнут; после вылазки уцелевшие снова у коек. Автоматчикам при найме — 150 патронов.
   **На вылазку — до четырёх** (`MAX_PARTY` в `game/mercs.js`).
2. **Скачивание и обновление:** релиз на GitHub, APK для Android (стабильная подпись debug-ключом),
   проверка новой версии в меню.
3. **Дальность стрельбы** реалистичная и затем уменьшена вдвое: СВД 18 м, ВСС 15, ПКМ 9, автоматы 7–8,
   ПМ и «Вектор» 6, дробовики 4–5 — у героя, наёмников и муров одинаковая.
4. **Локации на треть больше** (132×132 м, `HALF = 66`), кластер живёт 10–12 минут.
5. **Заражённые:** случайное число по опасности кластера, сильные (топтун, рубер) водят стаи.
6. **FPS:** отсечение по участкам, подстройка чёткости; модели глаже, оружие скруглено, граната Ф-1
   с рёбрами, гранаты в тайниках реже.
7. **Муры** — бандиты, стаб «Карьер» (около 50, лимит 50, раз в два часа пополняются): раз в 5–20 минут
   отряд 5–10 человек ходит в кластер кучей или парами, бьёт заражённых, выносит тайники, на добычу
   нанимает бойцов, остальное хранит в шкафах. «Карьер» можно атаковать (до 14 часовых, смена из казармы).
8. **Информатор** у лавки торговца: за 10 споранов говорит, где сейчас отряд муров.
9. **Муры убивают не так быстро:** по людям целятся 1–2 с, попадают и ранят слабее, разом стреляют
   не больше трёх по одному человеку (`MUR_AIM`, `MUR_ACCURACY`, `MUR_DAMAGE`, `MUR_SHOOTERS` в
   `game/murs.js`); тревога в «Карьере» расходится постепенно. Герой со 100 здоровья, стоя без движения
   у ворот под огнём всего «Карьера», живёт около 8 секунд.

10. **Кровь и разрушения до перезагрузки:** брызги, лужи, дырки от пуль, гарь и взорванные бочки держатся,
    пока кластер не перезагрузится (сохраняются в `saved.marks` / `saved.barrels` кластера, в том числе после
    гибели героя), после перезагрузки — чисто, вместе с новым лутом и заражёнными. Следы рисуются пачками
    (`game/marks.js`, InstancedMesh): после долгого боя 93 вызова отрисовки вместо 249.

11. **Графика без теней от солнца** (тени пользователь просил не делать): край кластера — светлая муть,
    асфальт и земля без повторяющихся пятен, разбросанные детали (`game/ground-detail.js`), картинка
    светлее, ободок по контуру персонажей, новые машины с ржавчиной и стёклами, тёплый свет фонарей и
    костров. Крыши домов пока тёмные — их пользователь отложил.

12. **Перенос на Godot (идёт):** пользователь выбрал перенести всю игру на Godot (под Android), у огнестрела —
    износ вместо патронов, новые стволы SCAR-H, FN FAL, Steyr AUG, PM-63 RAK, SPAS-12. Проект — `godot/`
    (Godot 4.4.1, рендер gl_compatibility). Ассеты не в git: их выгружает `scripts/export-godot.mjs`

    герой (AnimationTree, IK левой кисти, отдача, смена по стадиям), износ, заражённые, тайники, торговец,

    наёмники, муры, информатор, модели новых стволов, миникарта, звуки, настройки и счётчик FPS, графика

14. **Модели Tripo (идёт):** игрок и всё оружие (17) сгенерированы в Tripo (по 25 кредитов, скелет — 20; журнал —
    `docs/tripo/tripo_budget.md`), лежат в `godot/assets/tripo/` (текстуры ужаты до 1024 px — `scripts/glb-shrink.py`).
    Оружие (`godot/scripts/gear.gd`, `Gear.weapon`) вписывается в габариты старых моделей: дуло к дулу, узлы Muzzle и
    GripL — от старых; холодное — по главной оси и лезвию. Герой (`Gear.hero` + `godot/scripts/skin_follow.gd`):
    новая модель повторяет позу старого скрытого скелета — все 24 клипа, дерево анимаций и IK прежние; перенос —
    повороты костей + свои длины + IK рук и ног, модели развёрнуты лицом в одну сторону (Tripo-модель в файле смотрит
    вбок). Руки: у Tripo плечи на ~10 см дальше назад, запястье глубже в предплечье — поэтому оружие висит в хвате
    НОВОЙ кисти (`TripoGrip`, точка у костяшек), левая кисть ставится на цевьё этого оружия (ключица навстречу,
    перехват ближе), указательный вдоль коробки вне прицела. Длинный ствол вне прицела — в «переноске» по снимкам
    пользователя (поперёк корпуса, приклад у правого бока, левая ладонь под цевьём): `CARRY_*` в `hero_pose.gd`.
    Простого топора в Godot-версии нет (просьба пользователя): только красный пожарный («axe» из старых сохранений —
    он же, `Data.load_all`); топор и ствол в креплениях — за спиной новой модели (`SkinFollow.add_mount`,
    `axe_on_back`, `gun_on_back`), кобура — прежняя. Размер оружия — `Gear.target_length`: настоящая длина
    (`Gear.LENGTH`) × `Gear.SCALE` 0,67 (пользователь просил на треть меньше настоящего). **Правило пользователя:
    всегда сравнивать оружие с настоящим по размерам к человеку** — после любой правки размеров оружия или роста
    героя: `node scripts/weapon-sizes.mjs <файл.jpg>` (лист: в игре рядом с героем / в жизни рядом с человеком
    1,80 м) и показать его пользователю. Герой в игре ростом 2,06 м.
    Муры — две модели Tripo по картинкам пользователя (`godot/assets/tripo/mur_1.glb`, `mur_2.glb`, образцы —
    `docs/tripo/refs/`): клипы героя пересчитываются на их скелет один раз (`godot/scripts/skin_bake.gd`), дальше
    их играет обычный AnimationPlayer. Задания Tripo: ветка `tripo-control` (jobs.json; новый список — только новые
    задания, «stop» проверяется первым), исполнитель читает её из отдельной копии; номер проекта для скелета —
    `project list --size 2 --output-format json`.
    Оружие — 16 моделей Tripo по листу пользователя (`docs/tripo/refs/weapons`, модель по картинке, до 4000 треуг.):
    Glock 17, Desert Eagle, SPAS-12, двустволка, АКС-74У, АК-47, АК-74, АК-107, FN FAL, РПК, ПКТ, СВД, Arctic Warfare,
    Steyr AUG, HK G36, HK MP5 (ПКТ — только для установки на технику, в руки не берётся); старые стволы (ПМ, PM-63,
    «Вектор», обрез, МР-133, SCAR-H, ВСС, ПКМ) убраны по просьбе пользователя — в старых сохранениях становятся
    ближайшими новыми (`Data.REMOVED`, записи-псевдонимы с полем alias, в перечнях пропускаются). Посадка
    (`Gear.weapon`): оси — по старой модели или похожей (`FIT`), дуло у моделей по картинкам — к −Z (`MUZZLE`; у РПК
    сошки толще приклада), правая кисть — на рукоять, левая — на цевьё по разметке `HOLD` (доли габарита; размечать по
    сетке рендером сбоку). Муры и наёмники держат ствол как герой: `npc_pose.gd` (левая кисть на цевьё их ствола,
    переноска двуручного). В фотосъёмке CI — `guns_sheet.jpg`: герой с каждым стволом в переноске и прицеле. Муры — случайный ствол,
    больше всего АК (`MUR_GUNS` в `bandit.gd`). Заражённые — 4 модели Tripo по картинкам пользователя
    (`docs/tripo/refs/infected/`, `godot/assets/tripo/z_*.glb`): пустыш (вид runner), лотерейщик (новый вид lottery — между
    бегуном и топтуном, по решению пользователя; клипы бегуна), топтун, рубер. Клипы старых моделей (`Data.ENEMY` поле rig)
    пересчитываются на их скелет один раз на вид (`Enemy.make_model` → `SkinBake.instance(..., src)`): кости — по смыслу
    имени (`SkinFollow.src_any`: UpperArm.L → LeftArm), поза покоя А/Т поправляется (только для источника не Mixamo).

## Подводные камни

- `Batch.add` требует у геометрии uv и нормали (иначе `mergeGeometries` вернёт null) — `geom.js` их
  добавляет, но новые формы лучше делать сразу с uv.
- Покраска построек (`buildDacha` и др.) принимает материал (`M.woodGrey`), а не цвет.
- В тестах не ставить героя у самого выхода: удар или пуля отталкивают, и он уходит на карту Улья.
- Не скачивать пакеты (pip download и т. п.) в корень репозитория: `git add -A` их закоммитит (*.whl — в .gitignore).
- Пуш в ветку отменяет идущую сборку Godot (concurrency): длинная фотосъёмка со сценой хвата идёт ~25 мин — не пушить,
  пока ждёшь её результат.
- Телефон — главная платформа: следить за числом вызовов отрисовки и треугольников (тест печатает их
  в строке «нагрузка в кадре»), не раздувать число заражённых и муров.
