# Правила работы с Tripo

## 1. Бюджет
- Лимит этапа: **2000 кредитов**. Учёт в `tripo_budget.md`: модель, операция, цена, остаток.
- Перед каждой платной операцией сообщи: что делаешь, промпт, цену. Жди моего «ок».
  Исключение: если я одобрил план целиком — работай по плану без вопросов, но в его рамках.
- Остаток < 300 кредитов — остановись и спроси.
- Не перегенерируй вслепую. Плохой результат → объясни, что не так, предложи исправленный промпт, жди решения.
- Не трать кредиты на то, что можно сделать кодом или в движке (стены, полы, простые коробки, эффекты).

## 2. Качество с первой генерации
- Используй шаблоны из `PROMPT_TEMPLATES.md`.
- Единый стиль всей игры: реалистичный постапокалипсис, мир «Стикс» (Улей): потёртое, ржавое, грязное, приглушённые цвета. Никаких мультяшных пропорций.
- Один объект на генерацию, нейтральный фон, объект целиком в кадре.
- Сначала 1 тестовая модель → моё одобрение стиля → остальные.

## 3. Оптимизация под телефон (Android, Godot)
| Тип | Треугольники | Текстура |
|---|---|---|
| Игрок, NPC | до 10 000 | 1024 |
| Заражённые (обычные) | до 8 000 | 1024 |
| Мини-босс | до 12 000 | 1024 |
| Оружие | до 3 000 | 1024 |
| Крупная мебель | до 2 000 | 512–1024 |
| Мелкие предметы, лут | до 500 | 512 |
| Модули дома | до 300 | 512 (тайловая) |

- Режим: низкополигональный / Smart Mesh, формат **GLB**.
- Масштаб: 1 единица = 1 метр, точка опоры у основания модели, «вперёд» = -Z (как в Godot).
- Если модель превышает лимит — упрости (ретопология Tripo или декимация), не генерируй заново.
- После импорта каждой группы моделей: проверь FPS на тестовой сцене. Цель — стабильные **60 fps**, минимум 45 на среднем Android. Используй LOD и отсечение невидимого.

## 4. Персонажи и заражённые
- Генерация в **T-позе**, руки в стороны, ноги слегка расставлены, без оружия в руках.
- Сразу автоматический риг Tripo.
- Обязательные анимации для всех: покой, ходьба, бег, атака, получение урона, смерть.
- Игроку дополнительно: удар оружием ближнего боя, стрельба, подбор предмета, перекат/уклонение.
- Проверь, что анимации не рвут сетку и ступни не «едут» по земле. Только потом встраивай.
- Добавь кость/точку `hand_r` для крепления оружия.

## 5. Оружие
- Цельная модель, без разборных частей, без скелета.
- Взмах, удар, отдача, вспышка у дула, тряска камеры — кодом в Godot.
- Добавь узлы: `grip` (хват), `muzzle` (дуло, только огнестрел).
- Прочность и поломка — механика игры, не модель. При поломке — эффект частиц.

## 6. Дома и интерьер
- **Целые дома в Tripo не генерировать.**
- Модульный набор по сетке **2 × 3 м** (ширина × высота): стена, стена с дверным проёмом, стена с окном, внешний угол, внутренний угол, пол, потолок, лестница, крыша (скат, конёк). Это простые формы — сделай их в Godot кодом/примитивами, кредиты не трать. Tripo — максимум на 1–2 тайловые текстуры (кирпич, штукатурка).
- Сборка домов: GridMap с коллизиями. Из одного набора — несколько разных домов.
- Мебель: заметные предметы (телевизор, холодильник, диван, шкаф, стол, кровать, плита) — по одному на генерацию.
- Мелочь (банки, бутылки, коробки, книги, посуда): можно набором на одной картинке, затем сегментация Tripo на отдельные объекты. Проверь, что объекты разделились чисто; слипшиеся — не используй.
- Расстановку мебели по комнатам делай кодом/сценой, коллизии — простые формы (box/capsule), не по сетке модели.

## 7. Отчётность
- После каждой модели: скриншот в игре, треугольники, вес файла, потраченные кредиты.
- Коммит после каждой группы моделей.
