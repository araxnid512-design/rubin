# «Дрейф» — арт-пайплайн: 3D-модели → 2.5D-спрайты, тайлы, нормали

Всё в 2D (рендер Compatibility). Персонажи, дроны и турели — модели Tripo (GLB), запечённые в атласы
спрайтов с картой нормалей; пол и стены — процедурные тайлы. Свет в игре — `PointLight2D` + карты нормалей
(`CanvasTexture`), поэтому цвет запекается почти без светотени.

## 1. Проекция (общая для спрайтов, тайлов и кода игры)

- Ортографическая камера, наклон вниз 45° (pitch −45°), смотрит на «север» (−Z мира).
- **PPM = 64** пикселя на метр по горизонтали экрана.
- 1 м глубины пола → 64·sin45 = **45.25 px** по вертикали; 1 м высоты → тоже **45.25 px**.
- Точка мира (x вправо, z на юг/к зрителю, h вверх) на экране: `X = x·64`, `Y = (z − h)·45.25`.
- Тайл пола 1×1 м = **64×45 px** (не 46: картинки нечётной высоты; при раскладке шаг по вертикали 45 px,
  накопленная ошибка 0.25 px на тайл — незаметна).
- Стена 2.5 м: лицевая грань **64×113 px**; верх стены (толщина 0.4 м) — полоса **64×18 px**.

## 2. Направления

Персонажи и дроны — 8 направлений, турели — 16. Индекс 0 — лицом вниз по экрану (к зрителю, «юг»), дальше
**по часовой стрелке на экране**:

| индекс (8) | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
|---|---|---|---|---|---|---|---|---|
| куда смотрит | S (к зрителю) | SW | W | NW | N (от зрителя) | NE | E | SE |

Для 16 направлений шаг 22.5°: 0 = S, 4 = W, 8 = N, 12 = E.

Индекс считается по направлению **на плоскости пола** (в метрах мира, а не в пикселях экрана — диагональ
мира на экране выглядит круче, но модель поворачивалась именно в мире):

```gdscript
# dir — вектор взгляда на полу: x вправо, y на юг (к зрителю)
func dir_index(dir: Vector2, n := 8) -> int:
	return posmod(roundi(atan2(-dir.x, dir.y) / (TAU / n)), n)
```

## 3. Персонажи

- Кадр **128×128 px**, точка привязки (земля под корнем модели) — **(64, 100)**.
  Изначально было (64, 116), но снизу оставалось всего 12 px (0.27 м пола): шагающая к зрителю нога
  уходила на 20–25 px ниже точки и обрезалась. По согласованию с кодом игры точка поднята до (64, 100):
  снизу 28 px, сверху 100 px (макушка 1.8-метрового героя — на 82–93 px выше точки). Игра берёт `anchor`
  из json, значение по умолчанию в коде — `[64, 100]`.
- Рост модели приводится к **1.8 м** (≈81 px по вертикали) по габариту позы покоя (`--height`).
- Атлас на клип: **строки — 8 направлений, столбцы — кадры**. Файлы:
  `assets/sprites/<имя>/<клип>.png` (цвет), `<клип>_n.png` (нормали), `<имя>.json` (описание), `bake.log`.
- Клипы (12 fps):

| клип | кадров | цикл | источник Tripo | как выбирается отрезок |
|---|---|---|---|---|
| idle | 8 | да | idle (или wait) | самый «склеивающийся» отрезок 1.6–3.2 с из 15-секундного idle |
| walk | 8 | да | walk | ровно один цикл шага (левая + правая нога), найден по периоду позы |
| run | 8 | да | run | один цикл бега |
| attack | 6 | нет | box_01 (box_02, front_kick_01) | вся активная часть удара, корень прижат |
| shoot | 4 | нет | fire (shoot) | вся активная часть; `shoot` у Tripo — 9 с с перекатами, не годится |
| hit | 4 | нет | hit_to_body_01 (hit_to_head, hurt) | вся активная часть |
| death | 8 | нет, последний кадр держать | fall (defeat_02) | с 1.05 с (после спотыкания) до неподвижности |

  `defeat_02` у Tripo — поза «поражения» стоя (голова опущена), а не смерть, поэтому смерть — `fall`
  (падение на спину). Источник любого клипа меняется флагом `--map=attack:box_02` или файлом `--clips`.
- **«На месте»**: горизонтальное смещение кости-корня `Hip` убирается (логика как в
  `bunker/core/animation/anim_set.gd`, но поправка считается для каждого кадра в пространстве модели):
  у циклов — линейный дрейф за цикл плюс среднее (тело в среднем над точкой привязки, вертикальное
  покачивание остаётся); у attack/shoot/death корень прижат к точке в каждом кадре (`"root": "lock"`);
  у hit — линейно от первого кадра к последнему. Стык цикла сглаживается: поворот каждой кости к концу
  цикла доводится до позы первого кадра.

### json персонажа

```json
{
  "name": "hero", "kind": "character", "frame_w": 128, "frame_h": 128, "anchor": [64, 100],
  "fps": 12, "dirs": 8, "ppm": 64.0, "height_m": 1.8,
  "clips": {
    "walk": {"frames": 8, "loop": true, "src": "walk", "src_from": 0.3, "src_to": 1.467,
             "duration": 1.167, "native_fps": 6.86, "speed_native": 1.23, "speed_at_fps": 2.15},
    "death": {"frames": 8, "loop": false, "hold_last": true, ...}
  }
}
```

Обязательные поля — `frame_w, frame_h, anchor, fps, clips{name:{frames, loop}}`; остальные — подсказки:
- `native_fps` — с какой частотой играть клип, чтобы он шёл в родном темпе (idle ≈ 5 fps: 8 кадров на 1.6 с
  дыхания; при 12 fps стойка «дышит» в 2.4 раза быстрее);
- `speed_native` — скорость движения (м/с), с которой ноги не скользят при `native_fps`;
  `speed_at_fps` — то же при общих 12 fps. Масштабируйте `speed_scale` анимации под фактическую скорость.
- `hold_last` — после последнего кадра держать его (смерть).

### В игре

```gdscript
var ct := CanvasTexture.new()
ct.diffuse_texture = load("res://assets/sprites/hero/walk.png")
ct.normal_texture = load("res://assets/sprites/hero/walk_n.png")
sprite.texture = ct
sprite.centered = false
sprite.offset = -Vector2(meta.anchor[0], meta.anchor[1])   # позиция узла = точка на полу
sprite.region_enabled = true
sprite.region_rect = Rect2(frame * meta.frame_w, dir * meta.frame_h, meta.frame_w, meta.frame_h)
```

## 4. Дроны и турели

- **Дрон** (`--kind=drone`): 8 направлений × 1 кадр, клип `idle` (атлас 128×1024). Размер — наибольший
  горизонтальный габарит **0.8 м** (`--size`). Запечён висящим: низ корпуса на **1.0 м** над полом
  (`hover_m` в json), точка привязки (64, 100) — пол под центром дрона (там же рисовать тень). Покачивание —
  в коде игры.
- **Турель** (`--kind=turret`): высота **1.1 м** (`--height`). Модель автоматически режется по «шее» (самый
  узкий слой между основанием и головой, `--split=auto|none|<м>`):
  - `base.png` — основание, 1 картинка; `head.png` — голова в **16 направлениях** (атлас 128×2048), высота
    разреза — `split_m`. Основание и голову рисовать в одной точке привязки, голову поверх; голова
    вращается вокруг оси основания.
  - если «шеи» нет — `turret.png`, вся турель в 16 направлениях (`"split": false`).
  - направление 0 — ствол к зрителю (ствол ищется как самая дальняя от оси точка головы; `--yaw` — доворот).
- У обеих турелей Tripo разрез найден: пушка — 0.43 м, лазер — 0.23 м.

## 5. Цвет и нормали

- **Цвет** запекается ровным нейтральным светом: рассеянный 0.78 + мягкий ключ 0.32 сверху-слева
  (направление в пространстве камеры (−0.55, 0.62, 0.56)) + чуть светлее сверху, лёгкое затемнение у пола
  (до 0.6 м). Металличность/шероховатость Tripo не используются — это почти альбедо; объём дают 2D-лампы.
- **Нормали** — в пространстве камеры: `RGB = n·0.5 + 0.5`, **X вправо, Y вверх по экрану, Z на зрителя**
  (как ждёт Godot 2D: `CanvasTexture.normal_texture`, зелёный = «вверх по экрану»). Учитывается и карта
  нормалей модели Tripo (сила 0.7). Прозрачные пиксели — (128, 128, 255).
- Проверено `tools/bake/lit_test.tscn`: лампа слева — левая половина героя ярче (0.41 против 0.19), лампа
  справа — правая (0.25 против 0.10). Картинка — `docs/art/lit_test.png` (слева лампа слева, справа — справа).
- `PointLight2D.height` (пиксели) должен быть > 0, иначе поверхности, смотрящие на зрителя, не освещаются;
  в тесте 40. Ставьте лампу в точку экрана, куда проецируется её 3D-положение: у пола «ровная» нормаль
  наклонена вверх по экрану (0, 0.71, 0.71), у стен — вниз (0, −0.71, 0.71), поэтому лампа освещает пол под
  собой и стены, обращённые к ней, как в 3D.

## 6. Тайлы (`tools/gen_tiles.py` → `assets/tiles/`)

Процедурно (numpy + PIL): карта высот (в метрах) → нормали (тот же базис камеры) + альбедо → цвет с тем же
светом, что у спрайтов. Суперсэмплинг 4×4. Пол стыкуется со всех сторон, стены — по горизонтали.
У каждого тайла `<имя>.png` + `<имя>_n.png`; у светящихся — ещё `<имя>_e.png` (только свечение на чёрном,
для отдельного слоя с `blend_mode = ADD`, чтобы не гасло в темноте). Описание — `tiles.json`
(`file, normal, emission, size, kind, metres, alpha`). Всего ≈ 0.25 МБ.

| тайл | размер | что |
|---|---|---|
| floor_plate_a / _b / _c | 64×45 | палуба: 4 плиты; рифлёный лист; 2 плиты с люком |
| floor_grating | 64×45 | решётка |
| floor_hazard_n / _s | 64×45 | плиты с жёлто-чёрной полосой у северного / южного края |
| floor_airlock | 64×45 | шлюз: люк-диафрагма, шевроны |
| floor_reactor | 64×45 | реакторный отсек, голубые светящиеся линии (+ `_e`) |
| hull | 64×45 | внешняя обшивка корабля / обломков, вид сверху |
| rock_floor | 64×45 | астероид: камень с кратерами |
| wall_plain / _pipes / _console / _vent / _window | 64×113 | стены: панель, трубы, пульт (+ `_e`), вентиляция, иллюминатор со звёздами (+ `_e`) |
| wall_top | 64×18 | верх стены |
| door_closed / door_open | 64×113 | дверь 1 м; у открытой проём прозрачный (сквозь него виден пол за стеной), огонёк янтарный/зелёный (+ `_e`) |
| door2_closed / door2_open | 128×113 | дверь 2 м (два тайла) |
| rock_wall / rock_wall_top | 64×113 / 64×18 | каменная стена астероида (верхний край неровный, альфа) |

Раскладка: верх стены рисуется над лицевой гранью (грань занимает 113 px над линией пола, полоса верха —
ещё 18 px выше). Тайлы и спрайты с нормалями не зеркалить (`flip_h/flip_v`): значения нормалей при этом не
меняются, и рельеф начинает освещаться «наоборот» — поэтому полоса опасности дана в двух версиях (`_n`, `_s`).

## 7. Запуск

Нужен дисплей — под `xvfb-run`; Godot запускать по одному.

```bash
G=/home/user/godotengine/godot4
xvfb-run -a $G --path drift --rendering-driver opengl3 res://tools/bake/bake.tscn -- \
    --in=res://assets/src/sd_hero --out=res://assets/sprites/hero --kind=character
xvfb-run -a $G --path drift --rendering-driver opengl3 res://tools/bake/bake.tscn -- \
    --in=res://assets/src/sdp_turret_gun.glb --out=res://assets/sprites/turret_gun --kind=turret
drift/tools/bake/bake_all.sh        # всё: спрайты, тайлы, обзорные листы, проверка света
```

Флаги `bake.tscn` (полный список — `--help`):
`--in` (GLB, папка или префикс: для `sd_hero` берутся `sd_hero_a/_b/_c.glb`; модель — первый файл со
скелетом, клипы — из всех), `--out`, `--kind=character|drone|turret|sphere`, `--anims=<папка>` (ещё клипы:
`.res`/`.tres`/GLB), `--map=attack:box_02`, `--clips=<json>`, `--only=idle,walk`, `--height`, `--size`,
`--hover`, `--split`, `--dirs`, `--yaw`, `--frame=128x128`, `--anchor=64,100`, `--ss=3`,
`--preview=<клип Tripo>[,…] [--dir=6 --frames=16]` (полоса кадров всего исходного клипа — подобрать отрезок).

Устройство: SubViewport 384×384 (суперсэмплинг 3×) → второй SubViewport 128×128 с шейдером уменьшения
(усреднение с весом по альфе — без тёмной каймы; нормали после усреднения нормируются). Модель грузится
`GLTFDocument` прямо из GLB (импорт Godot не нужен), материалы заменяются шейдером
`bake_model.gdshader` (два прохода: цвет / нормали). Перед работой — калибровка: проверяется, переводит ли
рендер выход в sRGB, и шейдер подстраивается (в Compatibility под SubViewport — нет).

### Исходники (`assets/src/`)

- В папке лежит `.gdignore` — Godot её не импортирует и в APK она не попадает.
- `sd_<имя>_a.glb` — модель + скелет + idle/walk/run/turn/wait (как есть из Tripo);
  `_b.glb` (box_01, box_02, front_kick_01, dive, shoot, fire) и `_c.glb` (hit_to_body_01, hit_to_head, hurt,
  fall, defeat_02) — без текстур (`tools/bake/strip_glb.py`), из них берутся только клипы.
- `sdp_*.glb` — дроны и турели (статичные).
- Новая модель: `git fetch origin tripo-status`, `git show origin/tripo-status:files/<имя>.glb > drift/assets/src/<имя>.glb`,
  для `_b/_c` — `python3 drift/tools/bake/strip_glb.py вход.glb drift/assets/src/<имя>_b.glb`.
- Запасной герой (`assets/sprites/hero_fallback`) — из BunkerSurvival:
  `--in=$PWD/bunker/assets/models/hero.glb --anims=$PWD/bunker/assets/anim/hero`.

### Обзор

- `docs/art/sheet_<персонаж>.png` — все 8 направлений idle / walk / attack + нормали idle;
  `docs/art/sheet_props.png` — дроны и турели (цвет и нормали). Строит `tools/bake/contact_sheet.py`.
- `docs/art/lit_test.png` — тайлы + персонажи + турель + дрон под `PointLight2D` (`tools/bake/lit_test.tscn`).

## 8. Известные ограничения

- **death**: лежащее тело (1.8 м плюс раскинутые руки) не помещается в 128×128 при точке (64, 100) в
  части направлений — ноги/руки обрезаются краем кадра на 10–25 px в последних кадрах (больше всего у
  робота). Сдвигать тело в кадр не стали (по согласованию — тело остаётся над точкой привязки).
- Робот (самый широкий) в отдельных кадрах run/shoot/attack касается верхнего/нижнего края.
- Темп: все клипы в атласах по 12 fps, у idle родной темп ≈ 5 fps, у walk ≈ 7 fps (см. `native_fps`).
- Рост всех персонажей — 1.8 м, как в спецификации (робот задумывался 1.9 м — `--height=1.9`, если нужно).
