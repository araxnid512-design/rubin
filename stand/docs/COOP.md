# Кооператив на двоих — выделенный сервер (этап 1)

Что уже работает и проверено, что ещё нет — в конце.

## Как устроено
- **Сервер** — та же игра Godot 4.6, запущенная без экрана (`--headless`) со сценой `res://net/server.tscn`.
  Транспорт — ENet поверх UDP, порт **7777** (меняется параметром). Телефон первого игрока хостом не является:
  сервер — отдельная программа, выход одного игрока ничего не останавливает.
- **Узел сети** `ULNet` (`net/net.gd`) — один и тот же на сервере и на телефонах (`/root/Net`): телефон только
  просит (`c_hello`, `c_call`), сервер проверяет и отвечает (`s_reply`), а всем участникам мира рассылает новое
  состояние (`s_world`).
- **Состояние на сервере** — `ULServerState` (`net/server_state.gd`), один файл JSON с тремя резервными копиями
  (`.1 .2 .3`) и записью через временный файл (обрыв питания не портит сохранение):
  - игроки: имя, хэш секрета, личный кошелёк (спораны, горох, жемчужины), личный инвентарь, выбранный персонаж;
  - миры: код приглашения, владелец, участники (не больше двух), база — установленные улучшения, купленные
    маршруты, общие ящики; текущая миссия;
  - миссии: маршрут, участники, погибшие, вышедшие, время окончания, кто взял ключ главаря, открыт ли сундук;
  - номера выполненных операций — повтор той же просьбы (сеть переспросила) не выполняется дважды.
- **Профиль на телефоне** — `user://coop_profile.json`: постоянный идентификатор игрока и секрет (128+ бит).
  Сервер хранит только хэш секрета: чужой телефон с тем же идентификатором войти не может.

## Правила (их соблюдает сервер, а не телефон)
- Мир создаёт один игрок → код из 6 знаков → второй входит по коду. Третьего в полный мир не пускает; дальше
  в мир входят только его участники своими профилями.
- Общий ящик базы: положил один — видит и забирает другой. Если оба разом берут одно и то же — получает один,
  второму «уже забрали». Предметы и спораны клиенту не выдаются «на слово»: всё списывается и начисляется на сервере.
- Маршрут: платит купивший, маршрут становится общим, второму бесплатно, повторно не списывается.
- Улучшение базы (оружейник и т. п.) — так же: общее, платит купивший, второй раз не покупается.
- Миссия по купленному маршруту — одна на мир (вторую копию не создать), маршрут при старте расходуется.
- Гибель в миссии запоминается сервером навсегда для этой миссии: повторно войти нельзя ни из меню, ни после
  перезапуска приложения. Обрыв связи — не гибель: живой возвращается в ту же миссию, пока она открыта.
- Миссия закрывается, когда в ней не осталось живых (все погибли или вышли) или вышло время.
- Ключ главаря — тому, кто первым забрал его с тела; сундук открывает владелец ключа один раз, награду выбирает
  сервер по шансам `data/case.json`.

## Запуск сервера
Локально (для проверки):
```
godot --headless --path stand res://net/server.tscn -- --port=7777 --data=user://coop_server.json
```
На VPS (Linux, публичный IP):
1. Скопировать папку `stand` и Godot 4.6 (`Godot_v4.6.3-stable_linux.x86_64`).
2. Один раз импортировать ресурсы: `godot --headless --path stand --import`.
3. Открыть порт: `ufw allow 7777/udp` (и в панели хостинга — UDP 7777 входящий).
4. Служба systemd `/etc/systemd/system/stiks.service`:
   ```
   [Unit]
   Description=S-T-I-K-S coop server
   After=network.target
   [Service]
   ExecStart=/opt/godot/godot --headless --path /opt/stiks/stand res://net/server.tscn -- --port=7777 --data=/var/lib/stiks/coop_server.json
   Restart=always
   RestartSec=3
   User=stiks
   [Install]
   WantedBy=multi-user.target
   ```
   `systemctl enable --now stiks`; перезапуск — `systemctl restart stiks` (состояние сохраняется в файл).
5. Резервные копии: `coop_server.json.1 … .3` рядом с файлом данных; для надёжности — копировать папку
   `/var/lib/stiks` по расписанию (cron) в другое место.

В игре: главное меню → «МУЛЬТИПЛЕЕР» → адрес `IP:7777` → «Подключиться» → «Создать совместный мир» (код
передать напарнику) или «Присоединиться» по коду.

## Проверка
`res://net/net_test.tscn` — настоящий сервер отдельным процессом и три клиента со своими подключениями ENet:
```
godot --headless --path stand res://net/server.tscn -- --port=7790 --data=<папка>/server.json --grant=100 &
godot --headless --path stand res://net/net_test.tscn -- --port=7790 --phase=1 --dir=<папка>
# перезапустить сервер, затем:
godot --headless --path stand res://net/net_test.tscn -- --port=7790 --phase=2 --dir=<папка>
```
Результат в контейнере разработки: фаза 1 — 27 проверок из 27, фаза 2 (после перезапуска сервера) — 4 из 4.
