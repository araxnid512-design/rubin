# Живая книга: офлайн-квест

Текстовая ролевая игра для Android. Ты добавляешь свою книгу из памяти телефона, выбираешь героя и пишешь действия
обычными словами. Сцены сочиняет языковая модель Qwen3-0.6B, которая работает прямо на телефоне. Интернет не нужен:
у приложения нет разрешения на доступ к сети.

Реальные результаты проверок — в файле [ОТЧЁТ.md](ОТЧЁТ.md). Там же перечислено, что проверить не удалось.

## Что нужно, чтобы играть

Три файла из папки `dist/` и один файл модели:

1. **Приложение** — `zhivaya-kniga-debug.apk` (49 МБ). Модель и голос в него не входят.
2. **Модель** — файл GGUF, его нужно один раз скачать (ссылки ниже).
3. **Голос** — `golos-dmitri.zip` (67 МБ), встроенный русский голос «Дмитрий». Без него игра работает молча или через системный синтез речи.

### Шаг 1. Установить приложение

1. Скопируй `zhivaya-kniga-debug.apk` на телефон (по USB-кабелю в папку «Загрузки» или любым удобным способом).
2. Открой файл на телефоне. Android спросит разрешение на установку из этого источника — разреши.
3. Нажми «Установить».

Через компьютер то же самое делается командой `adb install zhivaya-kniga-debug.apk`.
Версия 1.1 ставится поверх 1.0 без потери сохранений.

### Шаг 2. Скачать и установить модель

Приложение принимает любую модель Qwen3 в формате GGUF размером до 2,5 ГБ. Проверены две:

| Модель | Размер | Что даёт | Ссылка |
|---|---|---|---|
| Qwen3-1.7B Q4_K_M | 1,1 ГБ | Связные сцены, персонажи отвечают по делу. Ход примерно вдвое дольше | `https://huggingface.co/unsloth/Qwen3-1.7B-GGUF/resolve/main/Qwen3-1.7B-Q4_K_M.gguf` |
| Qwen3-0.6B Q4_K_M | 397 МБ | Быстро, но текст небрежный и часто бессвязный | `https://huggingface.co/unsloth/Qwen3-0.6B-GGUF/resolve/main/Qwen3-0.6B-Q4_K_M.gguf` |

Контрольные суммы SHA-256:

- 1.7B: `b139949c5bd74937ad8ed8c8cf3d9ffb1e99c866c823204dc42c0d91fa181897`
- 0.6B: `ac2d97712095a558e31573f62f466a3f9d93990898b0ec79d7c974c1780d524a`

Проверить в Windows (PowerShell): `Get-FileHash имя_файла.gguf -Algorithm SHA256`.

Порядок действий:

1. Скачай файл модели на компьютер или телефон.
2. Скопируй его на телефон — во внутреннюю память или на карту памяти.
3. В приложении нажми **«Установить модель из файла»** и выбери этот файл.

Приложение проверит файл, скопирует его к себе и замерит скорость на твоём телефоне. После этого исходный файл можно удалить.
Модель можно заменить в любой момент: «Настройки» → «Заменить модель из файла». Сохранения при этом остаются.

Совет: начни с 1.7B. Если замер покажет, что ход идёт слишком долго, поставь 0.6B.

### Шаг 3. Установить голос

1. Скопируй `golos-dmitri.zip` на телефон.
2. В приложении открой «Настройки» → «Голос рассказчика» → **«Установить голос из файла»** и выбери архив.
3. Нажми «Прослушать пример».

Встроенный голос работает без интернета и без настройки системного синтеза речи.

Другой путь — системный синтез Android. Открой «Настройки» → «Системные настройки речи», выбери язык «Русский» и скачай
голосовые данные. Приложение использует только те системные голоса, которым не нужна сеть.

### Шаг 4. Играть

1. Включи авиарежим, если хочешь убедиться, что всё работает без сети.
2. «Добавить книгу» → выбери файл TXT, FB2, EPUB или PDF с текстом. Для пробы подойдёт `sample/vorota_mha.txt`.
3. Открой книгу, выбери героя и режим, нажми «Начать приключение».
4. Пиши действия в поле «Что ты делаешь?».

Быстрые команды без модели: `инвентарь`, `статус`, `журнал`, `задания`, `кто рядом`, `где я`, `сохранить`, `помощь`.

## Что умеет

- **Книги.** TXT (UTF-8, Windows-1251, KOI8-R, DOS-866, UTF-16 — определяется само, можно выбрать вручную), FB2 и FB2 в ZIP,
  EPUB, PDF с текстовым слоем. Сканы PDF, файлы с DRM и повреждённые файлы отклоняются с понятным сообщением.
- **Разбор книги.** Главы, фрагменты по 300–700 знаков, полнотекстовый поиск SQLite FTS5, карточки персонажей, мест, групп,
  предметов, правил мира и запертых мест. Разбор идёт по главам, его можно остановить и продолжить.
- **Сюжет.** У героя есть главная цель из книги. «Режиссёр сюжета» каждые три хода подбрасывает в сцену зацепку из очередной
  главы, иногда — осложнение, и постепенно ведёт историю по книге от начала к концу. Запечатанные места открываются найденным ключом.
- **Игра.** Свободный ввод, два режима («Ближе к канону» и «Свободная история»), герой книги или свой герой.
- **Правила.** Предметы, монеты, здоровье, место, отношения, задания и журнал ведёт движок правил. Модель пишет только сцену.
- **Память.** Раз в шесть ходов игра записывает сводку сюжета и держит её в памяти модели.
- **Сохранения.** Автосохранение после каждого хода, три ручных слота, «Переиграть последний ход», резервная копия в ZIP.
- **Озвучка.** Встроенный голос или системный синтез. Чтение по предложениям по мере генерации, пауза, продолжение, стоп, скорость, громкость.
- **Скорость.** Постоянный пул потоков, привязка к быстрым ядрам процессора, прогрев модели, пока ты читаешь сцену,
  подсказки без вызова модели, замер и подбор числа потоков.

## Чего ждать от модели

Модель пишет только текст сцены. С Qwen3-1.7B сцены получаются связными: персонажи отвечают по делу, упоминают то, что есть
в книге. С Qwen3-0.6B текст разнообразный, но грамматически небрежный и часто бессмысленный — это предел такой маленькой модели.
В обоих случаях мир не «плывёт»: за ним следят правила.

Настоящие ответы обеих моделей на одни и те же 35 ходов — в `docs/real-llm-run-1.7b.md` и `docs/real-llm-run-0.6b.md`.

## Сборка из исходников (Windows)

Нужны:

- Android Studio (любая свежая версия) или отдельно JDK 17–21;
- Android SDK: Platform 35, Build-Tools 35.0.0, NDK 27.2.12479018, CMake 3.22.1 (ставятся через SDK Manager в Android Studio).

Шаги:

1. Распакуй архив исходников, например в `C:\zhivaya-kniga` (путь без пробелов и русских букв).
2. Открой папку в Android Studio и дождись синхронизации Gradle — или в командной строке:
   ```
   cd C:\zhivaya-kniga
   echo sdk.dir=C:\\Users\\ИМЯ\\AppData\\Local\\Android\\Sdk > local.properties
   gradlew.bat :app:assembleDebug
   ```
3. Готовый файл: `app\build\outputs\apk\debug\app-debug.apk`.
4. Релизная сборка: `gradlew.bat :app:assembleRelease` → `app\build\outputs\apk\release\app-release.apk`.

Исходники llama.cpp уже лежат в `third_party/llama.cpp`, скачивать их отдельно не нужно.
Первая сборка нативной части занимает несколько минут.

**Про подпись.** Обе сборки подписываются ключом `keystore/zhivaya-kniga.jks` (пароль `livebook` записан в `app/build.gradle.kts`).
Это открытый учебный ключ частной сборки: он нужен, чтобы новые версии ставились поверх старых без потери сохранений.
Для публикации в магазине приложений создай собственный ключ.

**Сборка «всё внутри APK».** Если положить модель в `app/src/main/assets/model.gguf` и собрать проект, получится APK
около 425 МБ, который сам установит модель при первом запуске. Этот вариант в текущей среде не собирался и не проверялся.

## Тесты

```
gradlew.bat :core:test
```

Это 49 тестов логики (импорт, разбор, правила, сюжет, сохранения, игровой цикл) — они идут без модели.

Тест с настоящей моделью (Linux, нужны cmake и ninja):

```
cmake -S native -B build-host -G Ninja -DCMAKE_BUILD_TYPE=Release && ninja -C build-host livebook_llm
LIVEBOOK_MODEL=/путь/Qwen3-0.6B-Q4_K_M.gguf LIVEBOOK_NATIVE_DIR=$PWD/build-host ./gradlew :core:test --tests '*RealLlmIT'
```

Он проходит 35 ходов по тестовой книге и пишет протокол в `core/build/reports/real-llm.md`.

Тесты на телефоне или эмуляторе (нужен подключённый по USB телефон с включённой отладкой):

```
adb push Qwen3-0.6B-Q4_K_M.gguf /data/local/tmp/model.gguf
adb push dist\golos-dmitri.zip /data/local/tmp/voice.zip
gradlew.bat :app:connectedDebugAndroidTest
```

Они проверяют запуск интерфейса, импорт TXT и PDF, поиск по книге, сохранения, состояние голоса, установку модели и генерацию, установку встроенного голоса и синтез речи.

## Как устроен ход

1. Быстрые команды («инвентарь», «сохранить») выполняются сразу, без модели.
2. Перемещение определяется по словам игрока. Запертое место без ключа не пускает.
3. Из книги достаются 1–3 фрагмента: для текущего места и для действия.
4. «Режиссёр сюжета» решает, нужен ли в этой сцене поворот: зацепка из книги или осложнение.
5. Собирается короткий промпт: правила рассказчика, лор сцены, карточки персонажей рядом, состояние героя, цель, сводка сюжета,
   последние события, поворот, действие.
6. Модель пишет 2–3 предложения. Формат задан грамматикой (GBNF): только русский текст, без служебных слов.
7. Движок выводит изменения мира из слов игрока и текста сцены и проверяет каждое: взять можно лишь то, что есть в сцене,
   заплатить — не больше, чем есть, и так далее.
8. Ход записывается в базу одной транзакцией. Если модель дважды дала негодный ответ, игрок видит честное сообщение о сбое.
9. Пока игрок читает, модель в фоне обрабатывает начало следующего промпта и раз в шесть ходов пишет сводку.

Для маленькой и большой модели промпт разный: маленькой нужны образцы ответа и защита от самоповторов, большой — карточки персонажей.
